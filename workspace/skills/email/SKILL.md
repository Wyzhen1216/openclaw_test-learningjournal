# Email Assistant Skill

一个统一的 `email` skill，负责：

- 读取邮件
- 起草并发送邮件
- 邮件模板库
- 发送前二次确认
- 群发组管理
- 群组候选确认

不要把这些能力拆成平级 skill。对外始终把它当成一个“邮件助理”。

## 对外呈现

- 配合 workspace 使用时，默认以中文邮件助理身份对外工作
- 如果用户问“你有什么功能 / 你能做什么”，优先介绍邮件相关能力
- 不要主动暴露具体邮箱账号、SMTP / IMAP 主机、端口、密码等配置细节
- 只有用户明确追问当前邮箱配置时，才进入配置说明

## 分层说明

- `email-assistant.js`：上层主控入口，解析对话意图，管理模板、群组、待确认草稿
- `send-email.js`：底层发送执行器，可 CLI 调用，也可模块调用
- `read-email.js`：底层读信执行器，保持读信职责单一
- `send-email.sh`：兼容保留的 Bash 发送脚本

## 推荐用法

优先使用自然语言驱动 `email-assistant.js`：

```bash
node skills/email/email-assistant.js "给 张三<zhangsan@example.com> 发邮件，主题是“你好”，正文是“这是一封测试邮件”"
```

它会先检测模板库，再生成草稿，而不是直接发送。继续执行：

```bash
node skills/email/email-assistant.js "确认发送"
```

## 发信规则

- 所有自然语言发信请求都只能先生成草稿，不允许直接发送
- 真正发送只允许发生在当前存在待确认草稿、且用户明确回复 `确认发送` 时
- 如果没有待确认草稿，回复 `确认发送` 会明确提示当前没有可发送草稿
- 发信前会先检测模板库
- 若命中合适模板，会自动按模板起草，不再额外询问是否使用模板
- 若未命中模板，则按普通方式起草
- 无论是普通起草、模板起草、群组邮件还是群组+模板，都会进入同一套确认链路
- 草稿预览会明确显示起草方式、模板名、群组名、收件人、主题和正文

### 1. 模板库与自动套用

示例：

```text
帮我保存一个模板，名字叫“会议邀请”，主题是“关于{{topic}}的会议”，正文是“您好{{name}}，请于{{time}}参加{{topic}}。”
查看所有模板
查看模板“会议邀请”
删除模板“会议邀请”
用“会议邀请”模板给张三<zhangsan@example.com>发邮件，topic 是 项目评审，name 是 张三，time 是 明天下午 3 点
给 张三<zhangsan@example.com> 发邮件通知每天下午开组会
```

如果自然语言发信请求和模板库中的模板足够匹配，skill 会直接按模板起草；如果没有合理匹配，才会回退为普通起草。

### 2. 二次确认发送

任何真正发送的动作都必须先进入待确认状态。支持：

```text
确认发送
取消发送
修改主题为“新的主题”
修改正文为“新的正文”
收件人改成 王五<wuwu@example.com>
查看草稿
```

草稿预览示例：

```text
【草稿预览】
起草方式：群组+模板
模板：组会召开通知
群组：项目A组
收件人：
1. 张三 <zhangsan@example.com>
2. 李四 <lisi@example.com>
主题：组会召开通知
正文：
请大家从今天开始每天下午参加组会。
请回复“确认发送”继续，或回复“修改……”调整，或回复“取消发送”终止。
```

### 3. 群发组管理与候选确认

示例：

```text
创建一个群组叫“项目A组”，成员有张三<zhangsan@example.com>、李四<lisi@example.com>
查看所有群组
查看群组“项目A组”
给“项目A组”加一个成员王五<wuwu@example.com>
把“项目A组”里的李四删掉
删除群组“项目A组”
给“项目A组”发邮件，主题是“本周同步”，正文是“请大家今晚前反馈进度”
```

如果群组名不能精确命中，会先走：

1. 精确匹配
2. 轻量归一化匹配
3. 候选确认

发送场景下，当只命中候选而未精确命中时，不会直接发信，而是返回类似：

```text
未找到名为“测试群组”的群组。
你是不是想发给“邮件测试”？
回复“确认群组 邮件测试”继续，或回复“查看所有群组”。
```

确认群组后，skill 会继续恢复原起草流程。如果该请求命中模板，会直接生成“群组+模板”草稿；否则生成普通群组草稿。两种情况都仍然需要用户再回复“确认发送”才会真正发送。

### 4. 读取邮件

示例：

```text
查看最近 5 封邮件
查看 UID 4 邮件
查看 2026-03-18 16:50 之后的邮件
```

## 数据文件

- `templates.json`
- `groups.json`
- `pending-actions.json`

这些文件用于持久化状态，MVP 阶段不依赖数据库。

## 使用建议

- 发信时尽量使用 `邮箱` 或 `姓名<邮箱>` 格式
- 若要对群组发信，先创建群组再调用
- 群组名如果没有精确命中，可以先查看候选，再用 `确认群组 xxx`
- 若要稳定命中模板/群组管理，请尽量使用文档里的表达方式
